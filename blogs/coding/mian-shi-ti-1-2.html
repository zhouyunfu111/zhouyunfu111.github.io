    # flex布局理解

    flex布局是flexible box的缩写，意为“弹性布局”，用来为盒状模型提供最大的灵活性。任何一个容器都可以指定为flex布局。

    flex布局的主要思想是让容器有能力让其子项目能够改变其宽度、高度（甚至顺序），以最佳方式填充可用空间（主要是为了适应不同屏幕尺寸的设备）。

    采用flex布局的元素，称为flex容器（flex container），简称“容器”。它的所有子元素自动成为容器成员，称为flex项目（flex item），简称“项目”。

    容器属性：

    • flex-direction：决定主轴的方向（即项目的排列方向）
    • flex-wrap：定义如果一条轴线排不下，如何换行
    • flex-flow：是flex-direction属性和flex-wrap属性的简写形式，默认值为row nowrap
    • justify-content：定义了项目在主轴上的对齐方式
    • align-items：定义了项目在交叉轴上如何对齐
    • align-content：定义了多根轴线的对齐方式。如果项目只有一根轴线，该属性不起作用

    项目属性：

    • order：定义项目的排列顺序。数值越小，排列越靠前，默认为0。
    • flex-grow：定义项目的放大比例，默认为0，即如果存在剩余空间，也不放大。
    • flex-shrink：定义了项目的缩小比例，默认为1，即如果空间不足，该项目将缩小。
    • flex-basis：定义了在分配多余空间之前，项目占据的主轴空间（main size）。浏览器根据这个属性，计算主轴是否有多余空间。它的默认值为auto，即项目的本来大小。
    • flex：是flex-grow, flex-shrink 和 flex-basis的简写，默认值为0 1 auto。后两个属性可选。
    • align-self: 允许单个项目有与其他项目不一样的对齐方式，可覆盖align-items属性。默认值为auto，表示继承父元素的align-items属性，如果没有父元素，则等同于stretch。
    • align-items：定义了项目在交叉轴上如何对齐。

    # 任何监听transition的结束

    transition动画有两个事件

    开始事件: webkitTransitionStart

    结束事件: webkitTransitionEnd

    通过webkitTransitionEnd事件就可以监听

    # 任何监听transition animation的结束

    animation动画有三个事件

    开始事件: webkitAnimationStart

    结束事件: webkitAnimationEnd

    重复运动事件: webkitAnimationIteration

    通过webkitAnimationEnd事件就可以监听

    # grid布局理解

    gird布局是二维布局，即同时处理行和列。它将一个容器划分成一个个网格，可以任意组合不同的网格，做出各种各样的布局。以前，只能通过float、flex、table、inline-block等完成各种布局，现在grid布局使得布局更加简单、灵活。

    容器属性:

    • display: grid指定一个容器采用网格布局
    • grid-template-columns: 定义每一列的列宽
    • grid-template-rows: 定义每一行的行高
    • grid-template-areas: 定义区域
    • grid-template: 是grid-template-columns、grid-template-rows和grid-template-areas的简写
    • grid-column-gap: 列间距
    • grid-row-gap: 行间距
    • grid-gap: 是grid-column-gap和grid-row-gap的简写
    • justify-items: 定义项目在列轴上的对齐方式
    • align-items: 定义项目在行轴上的对齐方式
    • place-items: 是align-items和justify-items的简写
    • justify-content: 定义了项目在容器里面的水平位置
    • align-content: 定义了项目在容器里面的垂直位置
    • place-content: 是align-content和justify-content的简写
    • grid-auto-columns: 用来设置浏览器自动创建的多余网格的列宽
    • grid-auto-rows: 用来设置浏览器自动创建的多余网格的行高
    • grid-auto-flow: 定义了浏览器如何自动放置项目
    • grid: 是grid-template-rows、grid-template-columns、grid-template-areas、grid-auto-rows、grid-auto-columns、grid-auto-flow的简写

    项目属性:

    • grid-column-start: 定义了网格项目的起始列
    • grid-column-end: 定义了网格项目的结束列
    • grid-row-start: 定义了网格项目的起始行
    • grid-row-end: 定义了网格项目的结束行
    • grid-column: 是grid-column-start和grid-column-end的简写
    • grid-row: 是grid-row-start和grid-row-end的简写
    • grid-area: 是grid-area-start、grid-area-end、grid-area-start和grid-area-end的简写
    • justify-self: 定义了单个项目在列轴上的对齐方式
    • align-self: 定义了单个项目在行轴上的对齐方式

    # 使用window.addEventListener()监听事件,回调函数是普通函数里a对象调用了b方法，b方法是一个箭头函数，箭头函数的this指向哪里

    箭头函数的this指向定义时的上下文，而不是调用时的上下文。所以，箭头函数的this指向window。

    # 浏览器重绘与重排的区别？

    • 重排/回流：当DOM的变化影响了元素的几何属性（比如宽度、高度），浏览器需要重新计算元素的几何属性，将其安放在界面中的正确位置，这个过程叫做重排。表现为重新生成布局，重新排列元素。
    • 重绘(Repaint): 当一个元素的外观发生改变，但没有改变布局,重新把元素外观绘制出来的过程，叫做重绘。表现为某些元素的外观被改变

    单单改变元素的外观，肯定不会引起网页重新生成布局，但当浏览器完成重排之后，将会重新绘制受到此次重排影响的部分

    重排和重绘代价是高昂的，它们会破坏用户体验，并且让UI展示非常迟缓，而相比之下重排的性能影响更大，在两者无法避免的情况下，一般我们宁可选择代价更小的重绘。 『重绘』不一定会出现『重排』，『重排』必然会出现『重绘』。
